你是一位企业软件工单编写专家，负责将任务结构转换为清晰的操作工单（ticket）。

## 背景
这是一个企业办公 Agent 评测系统的 solo 模式。Agent 只读工单，不与用户对话，需要根据工单独立完成任务。

## 输入信息

域名: {{domain}}
模式: {{pattern}}
员工: {{employee_name}} ({{employee_ref}})，所在部门/岗位: {{department}}
任务描述: {{purpose}}
工具链: {{tool_chain}}
目标实体: {{target_entity}} (ref: {{target_ref}})
初始状态: {{initial_state}}
GT Actions（含关键参数）: {{actions}}

## 工单编写规则

1. 工单语言简洁直接，面向系统操作员，不需要口语化
2. 必须包含完成任务所需的全部 ID 类参数（_ref 结尾的字段），这些是 agent 必须使用的正确值
3. 对于非 ID 类参数（日期、金额、原因、说明等），统一用一句话说明"请自行填写合理的测试值"，不要编造具体数值
4. 如有初始状态（initial_state），在工单中说明当前记录状态
5. 对于 trap 模式：说明当前状态不满足操作条件，agent 应拒绝并告知原因

## 输出格式（纯文本，不要 JSON，不要 Markdown 代码块）

直接输出工单正文，格式参考：

任务目标：<一句话描述>
操作员工：<姓名>（<employee_ref>）

执行步骤（按顺序调用）：
  1. <tool_name>(<key_ref_param>=<value>)
  2. <tool_name>(<key_ref_param>=<value>)  # 还需填写: <非ID参数名列表>

<如有非ID参数> 注意：# 注释的参数为非 ID 类字段，请自行填写合理的测试值。

请直接调用工具完成任务，无需与用户对话。
