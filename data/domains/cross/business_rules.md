# CROSS 跨域业务规则

## 一、跨域任务基本原则

### 任务构成
- 每个跨域任务必须包含至少两个业务域的真实依赖链，单域任务不属于跨域范畴。
- 跨域操作须明确标注涉及的业务域和依赖关系，不可模糊处理。

### 执行顺序
- 跨域操作必须遵循"上游校验 → 下游执行 → 结果复核"的三阶段流程。
- 下游操作必须基于上游返回的真实数据执行，不可使用假设值或硬编码数据。
- 任何状态变更都要基于前置域返回的真实数据，不可凭空推断。

## 二、常见跨域场景

### 入职（HR + IT + Admin）
- 新员工入职时，HR 域完成 onboarding 流程后，IT 域须同步开通系统账号和邮箱。
- Admin 域须分配工位、门禁卡和办公设备。
- IT 账号开通须等待 HR 入职审批完成，不可提前创建。
- 工位分配须确认员工部门和办公地点信息（来自 Base 域）。

### 离职（HR + IT + Admin + Finance）
- 员工离职时，HR 域发起 offboarding 流程。
- IT 域须在离职当天回收所有系统账号权限（disable / deprovision），撤销数据访问授权。
- Admin 域须回收门禁卡、工牌、办公设备和工位。
- Finance 域须完成薪资结算、报销清算和借款回收。
- 各域操作须在 HR offboarding 流程到达对应步骤时触发，不可提前执行。

### 调岗（HR + IT + Admin）
- 员工调岗时，HR 域完成 transfer 审批后，IT 域须调整系统权限（新部门权限授予 + 原部门权限撤销）。
- Admin 域须处理工位调整（释放原工位 → 分配新工位）。
- 权限调整须基于 HR 审批结果中的新部门和新岗位信息。

### 采购付款（Purchase + Finance + Law）
- 采购订单执行后，Finance 域须根据收货验收结果创建付款申请。
- 付款金额须与采购合同和发票金额核对一致。
- 大额采购合同须经 Law 域法务审阅后方可签署。
- 付款须在验收完成后发起，不可提前付款。

### 项目费用（Work + Finance）
- 项目费用报销须关联具体项目（Work 域），费用科目须与项目预算对应。
- 项目预算超支时，Finance 域须拒绝报销或触发升级审批。

### 合同管理（Law + Purchase / HR / Finance）
- 采购合同由 Purchase 域发起，Law 域负责法务审阅和风险评估。
- 劳动合同由 HR 域管理，Law 域提供合规支持。
- 合同涉及付款条款时须与 Finance 域预算和应付账款对齐。

### IT 资产采购（IT + Purchase + Admin + Finance）
- IT 设备采购需求由 IT 域发起，通过 Purchase 域走采购流程。
- 采购到货后由 Admin 域进行资产入库和分配。
- Finance 域处理采购付款和资产折旧。

## 三、跨域数据一致性

### 员工信息一致性
- 所有域引用的员工信息（employee_ref）须来自 Base 域，各域不可自行维护员工主数据。
- 员工部门、职位、状态的变更由 HR 域驱动，其他域通过 Base 域获取最新信息。

### 审批链一致性
- 跨域业务的审批链须覆盖所有涉及的域，每个域的审批步骤独立执行。
- 某一域的审批被拒绝时，整个跨域流程应暂停，不可继续执行其他域的操作。

### 状态同步
- 跨域流程中，上游域的状态变更须及时通知下游域。
- 下游域操作失败时，须向上游域反馈错误信息，由上游域决定是否回滚。

## 四、合规约束

### 权限校验
- 涉及权限变更的跨域操作须满足各域本地的权限校验规则。
- IT 域的权限变更须基于 HR 域确认的岗位职责，不可超范围授权。
- Admin 域的资产分配须基于 HR 域确认的部门和办公地点。

### 费用合规
- 涉及费用的跨域操作须满足 Finance 域的预算控制和审批要求。
- 费用报销须关联真实的业务单据（采购单、差旅单等），不可无据报销。

### 合同合规
- 涉及合同签署的跨域操作须经 Law 域法务审阅。
- 合同条款变更须通知所有关联域的利益相关方。

## 五、异常处理

### 缺失上下文
- 跨域操作缺少关键上下文时（如上游域未提供必要数据），必须先补充证据，不能直接执行写操作。
- 缺失数据应通过查询上游域工具获取，不可使用默认值替代。

### 操作失败
- 跨域操作中某一步失败时，后续步骤不可继续执行。
- 失败信息须包含域名、操作名和具体错误，便于定位和修复。
- 部分域已完成的操作须评估是否需要补偿（回滚），补偿操作须由各域本地工具执行。

### 超时与重试
- 跨域操作应设置合理的超时机制，避免因单域阻塞导致整体流程卡死。
- 可重试的操作应标记为幂等（idempotent），确保重试不会产生副作用。

## 六、数据完整性
- 所有跨域引用字段（*_ref）须指向对应域中已存在的实体。
- 跨域操作须保留完整的操作日志，包含各域的操作时间、操作人和操作结果。
- 跨域任务的最终状态须由所有涉及域的操作结果综合判定，不可仅以某一域结果为准。
